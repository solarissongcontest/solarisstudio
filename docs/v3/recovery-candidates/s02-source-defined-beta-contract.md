## Alternative contract — S02-BETA-SOURCE

An isolated beta created **from scratch** may use the exact controlled source migration chain and the current verified S07 writer boundary. It has no historical production body dependency: it uses the actual source implementation, real permission engine, role grants, triggers and canonical commands. This is a different provenance claim, not a hosted-equivalent upgrade.

The executable profile is `s02-baseline-profiles.json`. Qualification requires:
- Exact Git SHA, pinned CLI/tool versions, one run-owned disposable local project and only loopback connection targets; reject inherited connection authority before SQL.
- Complete source migration versions, an initially empty user/ballot state, actual database identity/version and source hashes.
- A dependency report built from catalog bindings, conservative source-qualified references, trigger/policy/FK edges and actual function-call statistics. Each reachable node has a hosted comparison classification; unknown/different behavior is never converted into equivalence. Dynamic/unqualified/unexecuted branches remain explicit analysis limitations.
- Actual source strict-dual denial tests, canonical full 66-delegation contest including Grand Final/publication/Archive, all twelve ordered Archive recovery effects and existing refusal/rollback/restart/authorization/consequence tests.
- Real ballot/source/Results/replay tests with the corrected writer boundary installed, a second independent clean source replay/recovery, protected-definition equality and successful cleanup.
- Every required stage succeeds. Partial/stale evidence, missing safety scenarios, another database identity, dirty source or changed protected definitions cannot produce a qualification report.

The sole technical replacement is **baseline provenance** for this fresh isolated profile. Authorization, voting, Results, publication, Archive, historical integrity, idempotency and recovery assertions are retained. The scripts do not import production rows, secret values or unknown historical bodies; do not rewrite source/hosted migration history; and do not provision a paid service.

## What qualification does and does not unlock

The executable dependency consumer `assertBaselineDependency` (CLI `dependency`, explicit `S02_BASELINE_TARGET=fresh-isolated-source-beta`) rejects stale proof, changed constraints, missing stages and every hosted/existing-database target. It never enables a runtime write. A passing, integrated exact-SHA `SOURCE_DEFINED_ISOLATED_BASELINE_QUALIFIED` report may satisfy the **baseline dependency** of S06/S07-style testing **only when explicitly selecting this fresh source-defined beta target**. S06's original historical hosted-upgrade checkbox remains unproven. S07 source/behavior acceptance can use this fully declared source baseline instead of being recursively blocked on unrelated historical parity.

No report may approve an existing hosted upgrade, live beta, overall beta release, production recovery, public writes or a deployment. These fields are always false. Source qualification is not a server-enforced one-owner hosted rollout: access isolation, other beta release gates, actual infrastructure and any deployment authorization still have to be verified for that rollout. No owner terminal work or external technical reviewer is required by this contract.

The production obligation remains forward-only reconciliation of the real hosted frontier, including verified behavior of each reachable unmatched helper and the known remote migration-history discrepancy. Preserve the immutable October boundary. Existing comparators and all original negative gates remain intact.
