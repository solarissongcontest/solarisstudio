2. Release rulebook (no shortcuts)

1. No production tests in CI. Every Playwright, migration rehearsal, crawler, preview, audit and automated integration job must use an isolated local Supabase stack and loopback application target. Missing local infrastructure means fail closed. Preserve all egress guards.
2. One authority per critical domain. No second writer for Confirmation, Entry, Jury, Televote, Results, publication, Archive, identity, or edition/show state. Permissions must be proven by database grants/RLS/RPCs, not just React.
3. Migrations are System-owned. Do not run missing historical scripts against production blindly, rewrite old migration history, manufacture no-op entries, or make unapproved schema changes.
4. Every release gate is tied to the exact commit SHA. Build, Quality, Browser, S13, S14, S15, S16, security, Results, migration compatibility, performance/bundle, navigation and full-contest rehearsal evidence must come from that candidate.
5. Hard blockers = 0 and required conditional blockers = 0 for the intended released scope. Genuine missing mandatory workflows and unsafe writers cannot be reclassified as “debt” to meet the date.
6. Separate explicit approval is required before a hosted migration, a production deploy and opening public write workflows. No automation gets implied permission merely because CI is green.
7. Production recovery must be ready first: backup/restoration and rollback strategy, operator checklist, narrow smoke testing, error and egress monitoring, and correct replacement deadlines.

7. Definition of done (not negotiable)

The project may be described as “Solaris Studio V3 released” only when:

• The exact deployed commit SHA has a passing canonical release manifest.
• Every required launch capability has its documented product parity and migration/ownership classification; no unknown or silently dropped critical capability.
• Zero hard blockers and zero required conditional blockers for the full release.
• The production SQL migration frontier is legitimately reconciled and compatibility proven; no invented migration-history coverage.
• S14 full lifecycle, S15 ownership and S16 mutation-authority checks pass on the exact candidate.
• Official results, jury and televoting are secure, correct and publication-safe.
• Public, installed mobile and desktop experiences meet required navigation, safe area, accessibility and authorization acceptance.
• CI/Playwright uses only isolated local Supabase; no production egress regression.
• Release manager has explicit approvals, a rollback/recovery plan and real post-deploy verification.

If any item fails: preserve the integrity gates. An explicit limited pilot can be launched only with written owner approval, a documented smaller scope, hard blockers cleared for every exposed path and unfinished features disabled/unreachable. A pilot is progress, not completion.
